# Snow Spirit in Dungeon

เกม Top-down Dungeon Shooter เขียนด้วย Java Swing
ผู้เล่นเป็น Snow Spirit มี Fairy ลอยรอบตัวคอยยิงกระสุนใส่ศัตรู ต้องฆ่าศัตรูให้หมด เก็บกุญแจ แล้วเปิดประตูไปด่านถัดไป จนจบครบ 10 ด่าน
ระหว่างทางเปิดหีบสมบัติเพื่อรับยาและสกิล (โล่น้ำแข็ง / ดาบน้ำแข็ง)

---

## วิธีรัน

1. เปิดโฟลเดอร์ `SnowSpirit_Refactored` ใน VS Code
2. รัน `src/main/Main.java` (จะเปิดหน้าเมนูก่อน)
   (ต้องรันโดยให้ working directory เป็นโฟลเดอร์นี้ เพราะโค้ดโหลดรูปจาก `assets/...`)

**วิธีที่ง่ายที่สุด:** ดับเบิลคลิก `run.bat` (คอมไพล์ใหม่ทั้งหมดจาก `src` ลงโฟลเดอร์ `out` แล้วเปิดเกม ไม่ขึ้นกับแคชของ VS Code)

ถ้า VS Code ขึ้น error ว่าหาคลาสไม่เจอ (เช่น `Skill cannot be resolved`) ทั้งที่ไฟล์มีอยู่จริง
แปลว่าแคชของ VS Code เก่า: กด `Ctrl+Shift+P` -> **Java: Clean Java Language Server Workspace** -> **Reload and delete**

ถ้าจะรันจาก Terminal:

```
javac -encoding UTF-8 -d out -sourcepath src src/main/Main.java
java -cp out main.Main
```

## import ที่ใช้

ทั้งโปรเจกต์ใช้ import จาก Java แค่ 4 แบบ ซึ่งเป็นแบบเดียวกับตัวอย่างเกมในเอกสาร

```java
import java.awt.*;          // Color, Font, Graphics, Rectangle, Point, Image, Dimension, MediaTracker
import java.awt.event.*;    // KeyEvent, KeyAdapter, KeyListener, MouseEvent, MouseListener ...
import javax.swing.*;       // JFrame, JPanel, ImageIcon
import java.util.ArrayList;
```

- โหลดรูปด้วย `ImageIcon` (เหมือนเอกสาร) แทน `ImageIO` / `BufferedImage` / `File` / `IOException`
- สุ่มด้วย `Math.random()` (เหมือนคลาส Ghost ในเอกสาร) แทน `java.util.Random`
- A* ใช้ `ArrayList` + array ธรรมดา แทน `PriorityQueue`, `HashSet`, `Comparator`, `Collections`
- วาดด้วย `Graphics` เป็นหลัก ส่วนที่ต้องหมุน / โปร่งแสง / ขอบเรียบ (ดาบน้ำแข็ง, Boss จางหาย, Anti-aliasing) ใช้ `Graphics2D`, `AlphaComposite`, `RenderingHints` ซึ่งอยู่ใน `java.awt.*` อยู่แล้ว จึงไม่ต้อง import เพิ่ม
- เมนูขยับได้ด้วย `javax.swing.Timer` ซึ่งอยู่ใน `javax.swing.*` อยู่แล้ว
- import อื่นที่เหลือ เช่น `import main.GamePanel;` เป็นคลาสของเราเองที่อยู่คนละ package ต้องมีเพื่อให้คอมไพล์ได้

## ระบบ Hitbox กับแผนที่

**Hitbox = กรอบรูปที่วาด** ทุกตัว (เปิด Debug Mode จะเห็นกรอบตรงกับรูปพอดี)

| Entity | ขนาดรูป = Hitbox | ใช้กล่องกี่ช่องตอนเดิน (ช่องละ 64px) |
|---|---|---|
| Snow Spirit (Player) | 96 x 96 | 2 x 2 |
| Boss | 112 x 112 | 2 x 2 |
| Slime / Skeleton | 64 x 64 | 1 x 1 |
| Fairy | 32 x 32 | - |
| กุญแจ | 40 x 24 | - |
| กระสุน | 12 x 12 | - |
| ประตู | 128 x 64 | - |

**แผนที่สุ่มทุกด่าน** (MapGenerator)
- ขุดทางเดินด้วย "แปรง 2x2 ช่อง" -> ทางเดินและหัวมุมกว้างอย่างน้อย 2 ช่อง = 128px ใหญ่กว่าตัวที่ใหญ่ที่สุด (Boss 112px)
- ห้องกว้าง 4-7 ช่อง สูง 4-6 ช่อง ไม่ติดกัน
- ตรวจด้วย A* แบบกล่อง 2x2 ว่าเดินจากจุดเริ่มถึงประตูได้ ถ้าไม่ได้ สุ่มใหม่
- ช่องพื้นที่กล่อง 2x2 เข้าไม่ถึงจะถูกปิดเป็นกำแพง -> **ไม่มีซอกแคบที่ตัวละครเข้าไม่ได้**
- A* ของศัตรูคิดตามขนาดตัว (`new Pathfinding(map, blockSize)`) Boss จึงไม่เดินทะลุกำแพง

**การเดินของ Player**
- เดินแยกแกน X / Y ทีละ 1 pixel จนชิดกำแพงพอดี
- Corner Sliding: เยื้องเข้าทางเดินไม่เกิน 24px ตัวละครจะไถลเข้าเอง

## หลัก OOP ในโปรแกรม

### 1. Constructor

Constructor คือเมธอดพิเศษที่ชื่อเดียวกับคลาส ทำงานตอน `new` เพื่อกำหนดค่าเริ่มต้นให้ Object

| คลาส | Constructor ทำอะไร |
|---|---|
| `Player(GamePanel)` | ตั้งตำแหน่งเริ่ม, สร้าง Hitbox, โหลด Sprite, สร้าง `Fairy` |
| `Enemy(gamePanel, hp, speed, size)` | ตั้ง HP/ความเร็ว/ขนาด, สร้าง Hitbox, สร้าง `Pathfinding` ตามขนาดตัว |
| `Slime(gamePanel)` | เรียก `super(gamePanel, 3, 1, SIZE)` แล้วโหลดรูป Slime |
| `Main()` | สร้างหน้าต่าง ผูกปุ่มทุกปุ่มกับ ActionListener แล้วแสดงหน้าเมนู |
| `SettingPanel()` | วางปุ่ม God Mode / Debug Mode / Back |
| `Projectile(...)` | Normalize ทิศทาง แล้วคำนวณความเร็วแกน X/Y |
| `MapGenerator(width, height, roomCount)` | เก็บขนาดแผนที่และจำนวนห้องของด่าน |
| `Map(gamePanel, mapData)` | รับข้อมูลแผนที่ int[][] |

ตัวอย่างการเรียก Constructor ของคลาสแม่ด้วย `super(...)`:

```java
public Slime(GamePanel gamePanel) {
    super(gamePanel, 3, 1, SIZE);   // HP = 3, Speed = 1, ขนาด 64
    loadSprite("assets/Slime.png");
}
```

### 2. Encapsulation (การห่อหุ้มข้อมูล)

ซ่อนข้อมูลไว้เป็น `private` / `protected` แล้วเปิดให้ภายนอกเข้าถึงผ่านเมธอด (getter / setter)

- `Player` เก็บ `hp`, `x`, `y`, `hasKey`, `godMode` เป็น `private`
  ภายนอกอ่านได้ทาง `getHp()`, `getX()`, `hasKey()` และแก้ได้เฉพาะที่อนุญาต เช่น `setHasKey()`, `takeDamage()`
- `GamePanel` ซ่อน `enemies`, `map`, `debugMode` และเปิดเฉพาะ `getEnemies()`, `getMap()`, `toggleDebugMode()`, `addProjectile()`
- `Fairy` มี `getCenterX()`, `getAimX()` ให้ `Player` ใช้ยิง โดยไม่ต้องรู้ว่าคำนวณภายในอย่างไร
- `Enemy` ใช้ `protected` ให้เฉพาะคลาสลูกใช้ได้ ส่วนภายนอกใช้ `isAlive()`, `getHitbox()`
- `Node` ไม่ใส่ `public` เลย จึงใช้ได้แค่ภายใน package `ai`

ข้อดีคือ ค่า HP จะถูกลดได้ผ่าน `takeDamage()` เท่านั้น ซึ่งมีการเช็ค God Mode / ช่วงอมตะให้เสมอ

### 3. Composition (การประกอบ: "มี" Object อื่นอยู่ข้างใน)

ความสัมพันธ์แบบ **has-a**

- `Main` **มี** `MenuPanel`, `SettingPanel`, `GamePanel`
- `GamePanel` **มี** `Player`, `Camera`, `Map`, `Door`, `Level`, `ArrayList<Enemy>`, `ArrayList<Item>`, `ArrayList<Projectile>`
- `Player` **มี** `Fairy` (สร้างใน Constructor ของ Player)
- `Enemy` **มี** `Pathfinding` (ไว้หาทางเดินไปหา Player)
- `Level` **ใช้** `MapGenerator` และ `LevelMaps` เพื่อสร้าง `Map`

```java
public Player(GamePanel gamePanel) {
    ...
    fairy = new Fairy(gamePanel, this);   // Player has-a Fairy
}
```

### 4. Inheritance (การสืบทอด)

ความสัมพันธ์แบบ **is-a** ใช้ `extends` / `implements`

```
Enemy (abstract)                 Item (abstract)            JPanel
 ├── Slime                        ├── Key                    └── GamePanel
 ├── Skeleton                     └── Potion (abstract)
 └── Boss
```

- `Slime`, `Skeleton`, `Boss` สืบทอดของจาก `Enemy` เช่น `moveTowardPlayer()` (A*), `takeDamage()`, `drawHPBar()`, `updateAnimation()` จึงไม่ต้องเขียนซ้ำ
- `Key` สืบทอด `updateHitbox()`, `isPlayerTouching()` จาก `Item`
- `GamePanel`, `MenuPanel`, `SettingPanel` extends `JPanel` และ `Main extends JFrame` (เหมือนเอกสาร)
- การ implement interface: `Enemy implements Damageable`, `Player implements Damageable, KeyListener, MouseListener, MouseMotionListener`, `Potion implements Usable`

### 5. Abstract (คลาส / เมธอดนามธรรม)

คลาส abstract สร้าง Object ตรง ๆ ไม่ได้ ใช้เป็นแม่แบบให้คลาสลูก

- `abstract class Enemy` มี `abstract void update()` และ `abstract void draw(Graphics2D)`
  → ศัตรูทุกชนิด **ต้อง** เขียนวิธีเคลื่อนที่และวิธีวาดของตัวเอง
- `abstract class Item` มี `abstract update()` / `draw()` เช่นกัน
- `abstract class Potion` ยังไม่ได้เขียน `use()` จาก `Usable` จึงต้องเป็น abstract ไว้รอคลาสลูก (เช่น HealthPotion ในอนาคต)
- `interface Damageable` / `Usable` เป็น abstraction แบบสุดขั้ว คือมีแต่ชื่อเมธอด ไม่มีเนื้อหา

### 6. Polymorphism (หลายรูปแบบ)

ตัวแปรชนิดเดียว (`Enemy`) อ้างถึง Object ได้หลายชนิด และเมื่อเรียกเมธอดเดียวกันจะทำงานต่างกันตามชนิดจริง

```java
// Level.java — เก็บ Slime หรือ Skeleton ในตัวแปรชนิด Enemy
Enemy enemy;
if (Math.random() < 0.5) {
    enemy = new Slime(gamePanel);
} else {
    enemy = new Skeleton(gamePanel);
}

// GamePanel.java — เรียก update() แบบเดียวกันทุกตัว
for (Enemy enemy : enemies) {
    enemy.update();
}
```

- `Slime.update()` / `Skeleton.update()` → เดินตาม A* แล้วชนตัวผู้เล่นเพื่อทำดาเมจ
- `Boss.update()` → เดินมาถึงระยะโจมตีแล้วหยุด โจมตีดาเมจ 2 ทุก 1 วินาที
- `draw()` ก็ต่างกัน: Slime/Skeleton วาด Sprite Sheet แบบมีแอนิเมชัน ส่วน Boss วาดรูปเดี่ยว (หรือกล่องสีม่วงถ้าไม่มีรูป)
- `Item` ก็เช่นกัน: `for (Item item : items) item.update();` ไม่ต้องรู้ว่าเป็น `Key` หรือไอเทมอื่น
- `Damageable` ทำให้ทั้ง `Player` และ `Enemy` ถูกมองเป็น "สิ่งที่รับดาเมจได้" แบบเดียวกัน
- `@Override` ทุกจุดคือการเขียนทับเมธอด (Method Overriding) ซึ่งเป็น Runtime Polymorphism

## สรุปสิ่งที่เกมทำได้ตอนนี้

**หน้าเมนู**
- เลือกโหมดได้ทันทีที่หน้าแรก: การ์ด EASY / NORMAL / HARD (บอก HP ผู้เล่น, HP ศัตรู, ศัตรูเพิ่ม, คูลดาวน์วาร์ปของ Boss)
- START — เริ่มเกมด่าน 1 ด้วยโหมดที่เลือก
- HOW TO PLAY — ปุ่มควบคุม + อธิบายหีบ / กุญแจ / ยา / สกิล / สัญญาณเตือนของศัตรู
- SETTING — God Mode, Debug Mode, เสียง
- EXIT — ปิดเกม

**การควบคุมในเกม**
- `W A S D` / ลูกศร — เดิน (แอนิเมชัน 4 ทิศ)

### หลัก OOP ที่เพิ่มในรอบนี้
- **Abstract + Inheritance**: `abstract class Skill` -> `ShieldSkill`, `IceSwordSkill`
  คลาสแม่เก็บของที่ทุกสกิลมี (ชื่อ, ปุ่ม, Stamina, คูลดาวน์, เลเวล) คลาสลูกเขียนแค่ `activate()`, `isActive()`, `drawIcon()`, `getDescription()`
- **Polymorphism**: `Player` เก็บสกิลเป็น `Skill[] skills` แล้วเรียก `skill.update(this)`, `skill.draw(g, this)`, `skill.absorbHit(this)` โดยไม่ต้องรู้ว่าเป็นสกิลอะไร
  `absorbHit()` ของคลาสแม่คืน `false` เสมอ มีแค่ `ShieldSkill` ที่ Override ให้กันดาเมจได้
  ```java
  // Player.takeDamage()
  for (Skill skill : skills) {
      if (skill != null && skill.absorbHit(this)) {   // ShieldSkill กันได้, IceSwordSkill ไม่กัน
          return;
      }
  }
  ```
- **ขั้นตอนตายตัวในคลาสแม่**: `Skill.tryUse()` เป็น `final` (ตรวจคูลดาวน์ -> หัก Stamina -> `activate()`) คลาสลูกเปลี่ยนได้แค่ขั้น `activate()`
- **Inheritance**: `Chest`, `ChestKey`, `SkillScroll` extends `Item`, `StaminaPotion` extends `Potion`, `MenuButton` extends `JButton` (Override `paintComponent()`)
- **Composition**: `GamePanel` มี `Hud`, `SkillScroll` มี `Skill`, `Player` มี `Skill[]`, `Main` มี `HelpPanel`
- **Encapsulation**: Stamina เป็น `private` แก้ได้ผ่าน `useStamina(cost)` / `restoreStamina(amount)` เท่านั้น ซึ่งเช็ค God Mode และค่าไม่พอให้เสมอ
- **Polymorphism ของรางวัล**: `Chest.rollReward()` คืนค่าเป็น `Item` ไม่ว่าจะเป็น `SkillScroll`, `HealthPotion` หรือ `StaminaPotion`

### AI ศัตรูแบบใหม่ (ไม่ติดกำแพง)
- **Flow Field** (`ai/FlowField.java`): Breadth-First Search จาก Cell ที่ Player ยืน -> ทุก Cell รู้ว่าห่าง Player กี่ก้าว
  ศัตรูทุกตัวแค่เดินไป Cell ข้าง ๆ ที่ตัวเลขน้อยกว่า (คำนวณครั้งเดียวต่อการเปลี่ยน Cell ของ Player ใช้ร่วมกันทุกตัว)

- เดินอยู่ในเส้นกลางทางเดินเสมอ ถ้าเยื้องเกินจะขยับเข้ากลางก่อนค่อยเดินหน้า (Boss ตัวใหญ่ไม่เฉี่ยวมุม)

### แก้การเดินของศัตรู
ปัญหาเดิม: ศัตรูคำนวณเส้นทาง A* ใหม่ทุกครั้งที่ผู้เล่นเปลี่ยนช่อง แล้วเริ่มเดินไป "ช่องถัดไป" ของเส้นทางใหม่
ซึ่งบางครั้งอยู่ข้างหลังตัวเอง -> ผู้เล่นเดินขึ้น-ลง ศัตรูก็เดินขึ้น-ลงตาม ไม่เข้ามาสักที

วิธีใหม่ (`Enemy.navigateTo`):
- มองเห็นผู้เล่นตรง ๆ -> เดินตรงเข้าหาเลย (เคลื่อนที่แบบทศนิยม เดินเฉียงได้นุ่ม ไถลตามกำแพง)
- มีกำแพงขวาง -> ใช้ A* แต่คำนวณใหม่ทุก 20 เฟรม และกระโดดไปจุดที่ไกลที่สุดในเส้นทางที่มองเห็นได้
- ศัตรูดันกันเอง ไม่ซ้อนเป็นก้อนเดียว
- ทดสอบ: ผู้เล่นเดินขึ้น-ลงอยู่กับที่ ศัตรูตามทัน **12/12 ครั้ง** (เวอร์ชันเก่า 4/12)

### ศัตรู 2 ประเภท (`CombatStyle`)
| ศัตรู | ตีใกล้ (MELEE) | ตีไกล (RANGED) |
|---|---|---|
| Slime | HP 2, วิ่งเข้าชน | HP 2, อยู่ห่าง 220-340px, พ่นเมือกเขียว (ช้า ลูกใหญ่) ทุก ~2 วิ |
| Skeleton | HP 4, วิ่งเข้าชน | HP 3, อยู่ห่าง 260-380px, ปากระดูก (เร็ว ลูกเล็ก) ทุก ~1.7 วิ |

ตัวตีไกล: เข้าใกล้ = ถอยหนี, ไกลไป = เดินเข้ามา, ระยะพอดี = เดินวนด้านข้าง
ก่อนยิงจะเรืองแสง 0.4 วินาที ให้ผู้เล่นมีเวลาหลบ / มีวงสีใต้ตัว + หลอด HP สีม่วง ไว้แยกกับตัวตีใกล้
จำนวนตัวตีไกลของแต่ละด่านอยู่ในตาราง `SLIME_RANGED`, `SKEL_RANGED` ใน `LevelMaps.java`

### Boss
ยืนชาร์จ 0.6 วินาที มีวงแดงบนพื้นบอกพื้นที่ แล้วทุบ (ดาเมจ 2) -> เดินหรือ Dash ออกจากวงแดงทัน

### Dash
`Space` หรือ `Shift`: พุ่งไปทางที่กดเดิน (ไม่ได้กด = พุ่งไปทางเมาส์) 10 เฟรม ~140px
อมตะระหว่างพุ่ง (หลบกระสุน / วงแดงของ Boss ได้) คูลดาวน์ ~0.8 วินาที มีแถบบอกที่ล่างจอ

### เสียง (package `sound`)
สังเคราะห์เสียง 8-bit ด้วยโค้ด จึงไม่ต้องมีไฟล์เสียงใน assets ใช้ `AudioSystem` + `Clip` แบบในเอกสาร
ยิง, Dash, โดนตี, ศัตรูโดนยิง/ตาย/ยิง, Boss ชาร์จ/ทุบ, เก็บของ, กุญแจ, ดื่มยา, เปิดประตู, แพ้, ชนะ, กดปุ่มเมนู
เปิด/ปิดเสียงได้ในหน้า SETTING

### Effect ภาพ (package `effect`)
ประกายตอนยิง, หางกระสุน, ประกายตอนกระสุนชนกำแพง, ศัตรูโดนยิงกระเด็นถอยเล็กน้อย,
ศัตรูตายระเบิดเป็นเศษ + วงคลื่น + จอสั่น, ผู้เล่นโดนตีจอแดงวาบ + จอสั่น, เกล็ดหิมะตอน Dash,
Boss ทุบพื้นวงคลื่น + จอสั่นแรง, กุญแจเรืองแสง, ประกายตอนเก็บของ / ดื่มยา, ป้าย "LEVEL N" ตอนเริ่มด่าน

### ทดสอบความสมดุลใหม่ (มีศัตรูตีไกลแล้ว)
| Bot | ชนะ | เวลาเฉลี่ย |
|---|---|---|
| เล็งแม่นยำ หลบเก่ง | 8/8 | ~2.7 นาที |
| จำลองคนทั่วไป (หลบกระสุนได้แค่ 40%) | 6/8 | ~3.6 นาที |

## อัปเดตครั้งที่ 4

- Boss ใช้ Sprite Sheet `assets/Boss_Spirit.png` (4x4 เฟรมละ 128x128) เดินมี Animation และหันหน้าไปทาง Player ตอนตี
- ศัตรูโดนดาเมจ: เลิกใช้กรอบขาว เปลี่ยนเป็นกระพริบ + อมตะ 0.5 วินาที (30 เฟรม) แบบเดียวกับ Player และมีตัวเลขดาเมจลอยขึ้นเหนือตัว (`DamageText`)

- ระบบยาเสร็จแล้ว: `Potion` (abstract) -> `HealthPotion`, `SpeedPotion` แต่ละตัว override `use(Player)` ต่างกัน (Polymorphism ผ่าน interface `Usable`)
  ดรอปจากศัตรู, เก็บเข้ากระเป๋า 5 ช่อง (มุมล่างซ้าย), กด 1-5 เพื่อดื่ม, HP เต็มจะดื่มยาแดงไม่ได้

- Hitbox ของทุก Entity เท่ากับกรอบรูปที่วาด (ตารางด้านบน)

- import ยังคงมีแค่ `java.awt.*`, `java.awt.event.*`, `javax.swing.*`, `java.util.ArrayList` และแต่ละไฟล์ import เฉพาะที่ใช้จริง

## สิ่งที่เปลี่ยนจากโค้ดเดิม (ครั้งที่ 1)

การทำงานของเกมเหมือนเดิมทุกอย่าง ยกเว้นข้อที่ระบุว่าแก้บั๊ก

- แยกไฟล์เป็น package ตามหน้าที่ (`main`, `entity`, `entity.enemy`, `item`, `world`, `ai`, `interfaces`)
- เปลี่ยน field ที่เคยเปิดให้ทุกคลาสแก้ได้ ให้เป็น `private` + getter/setter
- ลดการขึ้นบรรทัดใหม่ที่ไม่จำเป็น และใส่คอมเมนต์ภาษาไทยแบ่งหมวด
- รวมเมธอดตรวจชนกำแพง 3 ตัวใน `Map` ที่ทำงานเหมือนกัน ให้เหลือ `isWallCollision(...)`
- ย้ายโค้ดวาดที่ Slime / Skeleton / Boss เขียนซ้ำกัน (กรอบโดนตี, กล่องสีแทนรูป) ขึ้นไปไว้ใน `Enemy`
- ย้ายแผนที่ด่าน 1 และ 3 ไปไว้ใน `LevelMaps.java`
- ลบแผนที่ตัวอย่างใน `Map` ที่ไม่ได้ถูกใช้ และตัวแปร `godmode` ใน GamePanel ที่ไม่ได้ใช้
- `Player` implements `Damageable` (เดิมมี `takeDamage` แต่ไม่ได้ประกาศ)
- **แก้บั๊ก:** หลังกด ENTER เริ่มเกมใหม่ Fairy จะไม่ขยับตามเมาส์อีก เพราะไม่ได้ใส่ `MouseMotionListener` คืน
- ถ้าไม่พบไฟล์รูป จะพิมพ์ข้อความสั้น ๆ แทน Stack Trace ยาว ๆ
